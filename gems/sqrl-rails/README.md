# sqrl-rails

SQRL login for Rails applications: an isolated engine that serves the SQRL protocol
endpoint, the status poll, the login callback and the browser script; ActiveRecord
stores; a view helper that renders the login block; and a sign-in adapter that plugs
into the authentication stack generated by `bin/rails generate authentication` (Rails 8)
or into any custom session scheme.

Devise applications should use [`devise-sqrl`](../devise-sqrl), which builds on this gem.

## Install

```ruby
# Gemfile
gem "sqrl-rails"
```

```sh
bin/rails generate sqrl:install   # migration, mount, initializer, User association, login block
bin/rails db:migrate
```

The generator:

- copies the `create_sqrl_tables` migration (`sqrl_identities`, `sqrl_nuts`,
  `sqrl_pending_logins`);
- mounts the engine: `mount SQRL::Rails::Engine, at: "/sqrl", as: :sqrl`;
- writes `config/initializers/sqrl.rb` (every option documented inline);
- adds `has_many :sqrl_identities` to `app/models/user.rb`;
- appends `<%= sqrl_login_block %>` to `app/views/sessions/new.html.erb` when that view
  exists (the Rails 8 generated login form).

Every step is idempotent. Options: `--host`, `--mount`, `--user-model`,
`--skip-migration`, `--skip-routes`, `--skip-views`.

## How a login works

1. `sqrl_login_block` issues a `sqrl://host/sqrl/cli?nut=…` URL, remembers the pending
   login in the browser session and renders the link, the QR code and the status text
   that `/sqrl/sqrl.js` drives.
2. The SQRL client POSTs its signed `query`/`ident` to `/sqrl/cli`. On success the
   identity is marked authenticated on the pending login and, when the client asked for
   Client Provided Session, a one-time token is handed back in `url=`.
3. The browser lands on `/sqrl/callback?t=TOKEN` (CPS) or, after the poller saw
   `{"authenticated": true}` on `/sqrl/status`, on `/sqrl/callback` with its own cookie.
   The callback resolves the user, signs them in and redirects.

## Configuration

`config/initializers/sqrl.rb`:

```ruby
Rails.application.config.sqrl.tap do |sqrl|
  sqrl.host = ENV["SQRL_HOST"].presence   # public host for sqrl:// URLs (default: request host)
  sqrl.user_class = "User"
  sqrl.on_unknown_identity = :create       # :create | :link | :refuse
  # sqrl.create_user = ->(identity) { User.create!(name: "SQRL user", password: SecureRandom.hex(32)) }
  # sqrl.sign_in = ->(controller, identity, user) { controller.send(:start_new_session_for, user) }
  # sqrl.after_sign_in = ->(controller, completion) { controller.send(:after_authentication_url) }
  # sqrl.failure_path = "/session/new"
  # sqrl.stores = :active_record           # or :memory, or an SQRL::Server::Stores
end
```

| Option | Default | Meaning |
| --- | --- | --- |
| `host`, `scheme` | request host; `sqrl` (`qrl` on plain-http loopback) | URL issued to clients |
| `on_unknown_identity` | `:create` | `:create` a user ({SQRL::Rails::UserFactory}), `:link` to the signed-in user, or `:refuse` |
| `create_user` | `UserFactory` | `(identity) -> user`; the default fills placeholder columns (random password, `sqrl-…@sqrl.invalid`) |
| `find_user` | by `user_ref` | `(identity) -> user or nil` |
| `current_user` | `Current.user`, else `session[:user_id]` | `(controller) -> user` used for `:link` |
| `sign_in` | `SignIn.default` | `(controller, identity, user)`; default calls `start_new_session_for` when the Rails 8 concern is present, else Warden, else `session[:user_id]` |
| `after_sign_in` | `after_authentication_url` / root | `(controller, completion) -> url`; a same-site `return_to` wins |
| `failure_path` | `/sqrl/login` | where a failed callback redirects |
| `stores` | `:active_record` | storage back end |
| `nut_ttl`, `cps_token_ttl`, `require_ip_match`, `ask`, `sin`, `path_extension`, `on_authenticated` | see `SQRL::Server::Config` | protocol options |

### Rails 8 `generate authentication`

Nothing to configure: when `Authentication` (the generated concern) exists, the
callback controller includes it and calls `start_new_session_for(user)`, so SQRL logins
produce the same `Session` rows and cookies as the password form, and
`after_authentication_url` sends the browser back to the page that required login.

### Custom session schemes

Set `sign_in` (and usually `after_sign_in`) to whatever your application does; `identity`
is an `SQRL::Server::Identity` (`idk_b64`, `user_ref`, `disabled?`, …).

## Helpers

In views: `sqrl_login_block(return_to:, cancel_url:, link_user:, script:, **login_block_options)`,
`sqrl_login_url`, `sqrl_qr_svg`, `sqrl_script_tag`, `sqrl_status_path`, `sqrl_script_path`.
In controllers: `current_sqrl_identity`, `sqrl_authenticated?`, `sqrl_logout!`
(call it from your sign-out action), `sqrl_endpoint`.

## Storage

`SQRL::Rails::Identity` (`sqrl_identities`): `idk`, `suk`, `vuk` (base64url), `disabled`,
`sqrlonly`, `hardlock`, `ins`, `logins`, polymorphic `user`, `superseded_by` (tombstone
rows left by a re-key), `last_login_at`. `SQRL::Rails::Nut` and
`SQRL::Rails::PendingLogin` are single-use records; `bin/rails sqrl:prune` deletes the
expired ones (run it from cron or a job).

Nut consumption and CPS-token claims are single conditional `UPDATE`s, so they stay
single-use under concurrent requests.

## Linking identities to existing accounts

With `on_unknown_identity = :link`, unknown identities are only accepted while a user is
signed in; render `sqrl_login_block` on an authenticated settings page and the new
identity is attached to `Current.user` (or whatever `current_user` returns).
